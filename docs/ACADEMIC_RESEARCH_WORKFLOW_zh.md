# 学术科研资料库 v1.1.0：从文献到实验与写作

目标是让文献、教材、方法依据、原始数据、处理代码与论文写作互相可追溯。
IFFT只是一个应用项目。本次提供的是本地工作流基础，仍是命令行菜单；
没有宣称已完成联网AI问答平台、语义检索或自动写论文。

## 从1.0.0升级

1. 在GitHub下载最新完整ZIP并解压到一个新的程序目录，或更新现有clone。
   不要把解压后的代码误当成资料库；数据目录仍使用原来的那个。
2. 在解压后的仓库根目录打开PowerShell，安装PDF依赖（只需首次或更新依赖时执行）：

   ```powershell
   py -3 -m pip install -r tools\requirements-library.txt
   ```

   若没有`py`而启动器使用`python`，把上面的`py -3`替换成`python`，确保使用同一个Python。
3. 关闭旧版菜单，双击新版 `START_RESEARCH_LIBRARY_WINDOWS.cmd`。
   确认显示 `1.1.0`，输入原资料库路径。
4. 选择 **2**。补充新目录和 `RESEARCH_WORKFLOW.md`，保留已有目录、数据和用户规则。
   旧版根目录AGENTS.md不会被覆盖；新工作流说明单独保存。
5. 把论文PDF放到 `01_Literature`，教材放到 `07_Textbooks`。
   也可以先放 `00_Inbox`，选择3预览、4分类复制。未明确命名的PDF不会自动识别为教材。
6. 选择 **7** 建立全文索引；随后 **8** 输入关键词（如 `forbidden reflection`）。
   首次建议仅放2–3篇论文和一本教材，检查提取报告和命中页。
7. **9** 输入资料库内相对路径与页序，建立阅读/写作分析卡；**10** 建立项目；**11** 查看指定原文页的提取文字。

程序不自动更新已下载代码，不实时同步，不在后台监视新资料。文件新增或变动后需再次选择7。
大型教材索引可能较慢，90_Index会保存每次提取的全文副本；不要把全文缓存误当成不占空间的目录索引。

## 检索的准确含义

- `index`是文件字节/SHA256索引；`text-index`是PDF/TXT/MD内容索引，二者不同。
- 每次提取在90_Index创建独立SQLite文件与JSON报告。未写完报告的中断任务不会被选为最新索引。
- PDF逐页存文字及状态；页序从1开始，**不是书上印刷页码**。TXT/MD按一个文本记录，页码不适用。
- `find`做不区分大小写的字面短语匹配，并合并连续空白；支持中文，但不做同义词、词干或语义扩展。
  输出片段会归一化大小写/空白，**不能作为逐字引文**；逐字引用请打开原文核实。
- 命中原文件重新计算SHA256，若修改、删除或不允许访问则不返回旧片段。新增文件在重建前不会进入索引。
- 同一SHA256的同一页去重；Inbox与分类目录的相同副本不是两篇独立文献。
- 无提取文字页列为warning；损坏/加密/读取失败列为error。部分失败时仍可搜索成功索引的文件，但报告保留失败状态。
- 搜不到≠原文没有。图表、公式、双栏顺序、扫描PDF都可能影响提取，需要查看原页。
- pypdf不提供OCR；本版不自动处理扫描文字。依据：[pypdf官方文字提取说明](https://pypdf.readthedocs.io/en/6.21.1/user/extract-text.html)。
- 文本提取版本锁定 `pypdf==6.10.0`，与本次测试环境一致，不意味着永远无需更新。

## 怎样支持写作而不丢失科学依据

阅读卡包含原文相对路径、SHA256、PDF页序和待核实的书目信息。标题、作者、DOI、主题需要填写，不从文件名猜测。
方法卡记录样品、实验/处理条件、参数、证据与限制；写作卡记录引言逻辑、段落功能、图与论点的对应关系。
创建卡片不会自动读懂论文、生成综述或证明方法适用于我们的样品。

每个研究项目有：

- `evidence.csv`：主张 → 文献路径与指纹 → 页码/图号 → 作者陈述或推断 → 适用性与限制。
- `experiments.csv`：研究问题 → 原始数据指纹 → 代码commit → 参数 → 输出 → 观察与解释。
- `manuscript_outline.md`：论文结构，随后由人工或有权限的助手依据证据填写。

例如，讨论“IFFT幅度能否界定真实晶界”时，要分别查教材的成像/滤波原理、论文的具体处理方法和我们自己的实验验证；不能仅因为某论文采用一种显示方式，就认定它测量了真实晶界。

## 给后续助手的任务示例

在已经授予本地文件权限的会话中可以要求：

> 先查本资料库中关于TEM Fourier filtering和inverse Fourier transform的资料。
> 打开命中论文的原文方法段与补充材料，列出文件路径、PDF页序、图号和明确参数。
> 区分原文陈述与推断，再和本项目代码比较；资料不足时说明缺口。

> 阅读09_Writing/Examples里指定文章，填写写作分析卡：每段承担什么功能，
> 每个结论由哪张图支持，如何表达不确定性。用我的结果另写提纲，不复制原文。

目录存在、脚本能运行、GitHub已连接均不能单独建立本机到当前聊天的远程访问。
本工具无上传/网络功能；需另用已支持并授权本地目录的会话，或显式上传需要分析的资料。
